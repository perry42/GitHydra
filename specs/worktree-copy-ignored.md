# Copy ignored files into a new worktree, with a per-repo memory

Status: BUILT, not merged (branch feat/copy-ignored; security-reviewed with its changes applied, the reviewer agreed with remembering a hand-ticked secret on the condition that directory rows are classified by their contents, which is done; POSIX-only checks (O_NOFOLLOW, 0600, case-insensitive collisions) are not exercised on the Windows dev machine and should run on CI; see Review log; the owner can overrule). Split out of the worktrees spec on review (2026-10-13). Reviewed by security-reviewer, product-manager and test-agent; second security pass on the revised text pending (see "Review log"). Owner: product-manager. Needs a security review before build (copies files between folders). Companion of `specs/worktrees.md` (the create dialog's Advanced section). Owns FR-626..631 and FR-643. Default stance: GitKraken's worktree docs say nothing about ignored files, so this is a GitHydra improvement; no other git GUI has a per-file checklist with sizes and secret flags.

Visual truth: the approved clickable mockup after the Impeccable fixes and the replacement of the Remember block. This text wins over the mockup.

## Problem
A new git worktree contains only tracked files. Ignored local files (`.env`, `.vscode/`, local config) are missing, and carrying them over by hand is tedious. Doing it silently would be dangerous: a secret could be copied somewhere the user did not expect.

## Target user
A developer who creates worktrees several times a week (or per agent session) and whose repos need a few ignored local files in every worktree.

## Product rules this spec must not break
Nothing is copied that the user has not seen named. No script runs. Nothing is written into the user's repo or `.git` by GitHydra. A file in a repo (`.worktreeinclude`) is untrusted input. No network, no account, no telemetry.

Principle: **the list remembers; the checkbox is for this time.**

## F. Behavior
- **FR-626 Candidates.** git itself lists them in the SOURCE worktree (the one the user created from): `git ls-files -o -i --exclude-standard -z --directory`. Directories are rows; a directory row shows a file count and size (size computed asynchronously and capped, with a "size not computed" fallback) and expands to its enumerated files at copy time. A nested repo or submodule directory is shown disabled ("separate repository, not copied"). Bare repo or zero candidates: render nothing. The git child process is killed on the 5 s timeout (the whole tree on Windows); stdout is capped at 4 MB and the manifest at 20,000 rows ("too many files to list" beyond that). git-core re-enumerates at Create time and refuses any requested path outside that fresh set; the renderer, the memory and `.worktreeinclude` are hints only.
- **FR-627 What is ticked on open.** In this order: (1) remembered paths that are still candidates (including secret-looking ones the user ticked by hand on an earlier create, see below); (2) otherwise `.worktreeinclude` matches that are not secret-looking, not on the run-code list below, and fit the budget (at most 20 rows, 20 MB in total, nothing flagged large); (3) otherwise nothing. Once a repo has a record, **including an empty one (`paths: []`, the user chose to copy nothing)**, the user's memory wins over the file: step (2) applies only when no record exists, so a `.worktreeinclude` that appears or changes later never re-seeds ticks or reopens Review for that repo. **Secret-looking rows are never pre-ticked from a repo file or from `.worktreeinclude`; they may be pre-ticked only from the user's OWN memory** (owner decision 2026-10-13, reversing the earlier "never remember"): a remembered secret such as `.env` is ticked on the next create, always shown with its secret warning on the collapsed line (FR-628), tagged "remembered" and "secret", and can be unticked in one click; a secret-looking path enters the record only if the user ticked it by hand on that create (FR-629). Security-reviewer agreement on this point is required before merge (it was the reviewer's recommendation to keep "never"; the owner chose convenience with these mitigations). Secret-looking = `.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `id_*`, `credentials*`, `.npmrc`, `.netrc`, `.pypirc`, `*secret*`, `*token*`, `*password*` (name-pattern based, so a false positive costs a warning and a false negative such as `config/local.json` is not caught; the list is a table test, implemented as simple prefix/suffix/substring checks, never backtracking regexes). **Run-code names** (`.envrc`, `.vscode/tasks.json`, `.vscode/launch.json`, `.vscode/settings.json`, `.idea/`, `.husky/`, `.githooks/`, `.devcontainer/`, `.claude/`, `.cursor/`, `.zed/`, `.cargo/config.toml`, `.yarnrc.yml`, `.yarn/`, `.mise*`, `.direnv`, `.mvn/`, `.bundle/`, `.pre-commit*`, `.lefthook*`; these are build-time table entries, extended as editors and tools add run-on-open config) run code when the new worktree is opened in an editor or shell: they are tagged "runs code when opened" and never pre-ticked from `.worktreeinclude`. **Large** = a directory named `node_modules`, `target`, `dist`, `build`, `.venv`, `venv`, `vendor`, `.gradle`, `Pods`, or any row of at least 50 MB or 5,000 files.
- **FR-628 The line and the Review list.** One line, always visible in the dialog body under "Open after create" (never inside Advanced, which holds only the detached-HEAD option; nothing is ever copied with the line hidden). With zero candidates it reads the muted line "No ignored files to copy in this repository."; in a bare repository, "This is a bare repository: there is nothing to copy." (amended 2026-10-18 after the owner never found the line inside Advanced). **Review default (amended 2026-10-18):** when this repo has NO record yet and at least one candidate, the Review list is open by default (`aria-expanded="true"`, focus stays in the Folder field) so the first create shows and teaches the ticks; when a record exists the one-line summary stays with Review closed (the user can open it). Zero-candidate, bare and failed states are unchanged. The list never scrolls on its own; the dialog body scrolls and the footer buttons stay visible. Warning marks are a triangle icon plus the word "secret", never colour alone. Exact strings (`·` is a middle dot, `...` is three dots, not an ellipsis character; sizes under 1 KB read `N B`, otherwise rounded to the nearest KB or MB with a minimum of `1 KB`; `1 file` vs `N files`; `1 secret file` vs `N secret files`):

  | State | Text |
  |---|---|
  | Checking | `Checking for ignored files...` (`aria-busy`) |
  | Candidates, nothing ticked | `No ignored files will be copied.` + `[Choose files]` |
  | Ticked from memory | checkbox (on) + `Copy 3 files · 4 KB` + muted `remembered for this repo`; second line `.env, .vscode/, config/local.json` (3 names, then `and N more`) |
  | Ticked from the file | checkbox (on) + `Copy 2 files · 3 KB from .worktreeinclude` |
  | A ticked row is secret | `[triangle] 1 secret file: .env` / `2 secret files: .env, .npmrc` |
  | File lists secrets, unticked | `[triangle] .env is listed in .worktreeinclude but looks like a secret, so it is not ticked.` (plural: `2 files listed in .worktreeinclude look like secrets, so they are not ticked: .env, .npmrc.`) |
  | Skipped this time | checkbox (off) + `Copy 3 files` + muted `skipped this time`, rows disabled but visible |
  | Listing failed or over 5 s | `[warning] Couldn't list ignored files. The worktree will be created without copying.` + `[Try again]` |

  After the user edits ticks, the "remembered for this repo" and "from .worktreeinclude" wording is dropped (it would no longer be true). Review expands: intro `A new worktree has only tracked files. Tick the ignored files you want copied.`; `[Select none]` only when something is ticked (no "Select all"); ONE list-level warning when a secret row exists (`Rows marked "secret" look like passwords, tokens or keys. Copy them only if the new worktree needs them.`); rows = checkbox + name + tags + size, ticked rows first, then rows listed in `.worktreeinclude`, then the rest; the list caps at 6 rows with "Show all N" (no nested scroller); tags: `secret`, `remembered`, `in .worktreeinclude`, `runs code when opened`, `large, consider reinstalling`; a symlink row is disabled (`symbolic link, not copied`); a name with control or bidi characters is shown with those characters visible and the row is disabled (`name not allowed`); `Skipped: these patterns point outside the repository` lists rejected `.worktreeinclude` patterns. Footer, the whole disclosure of remembering: `Changes you make here are remembered for this repository, on this computer.` A polite live region announces `3 files selected, 4 KB`. Keyboard order: Folder, Browse, copy checkbox, Review, rows, Select none, Cancel, Create.
- **FR-629 Memory.** One record per repository in the renderer's guarded `localStorage` (same pattern as `ignorePrefs.ts` and `useIdentityApplications.ts`; reads and writes never throw). The key is the sha256 `computeRepoKey` of the git common dir's realpath, **delivered over IPC by the main process** (`electron/recoveryDrafts.ts`; the renderer cannot compute a realpath; the key IPC takes NO argument and returns the key for the active repo only, like `session.getOpenRepo()` for recovery drafts, because a "key for path X" call would be a realpath-existence oracle; the key is not a security boundary, the record is only a hint), so the main checkout and every linked worktree share one record and two clones do not; the raw path is never stored. Value `{v:1, paths:[...], at}`; paths exactly as git reports them (directories end in `/`); no contents, sizes or hashes. Caps: 200 paths per record (the 201st is dropped), 200 records (oldest `at` evicted; ties broken by a monotonic counter). **Save rule:** on a successful `git worktree add`, with the checkbox on and the final ticked set different from the initial one (set equality over path strings; "visible" means candidate rows regardless of the 6-row cap), write the final ticked paths plus remembered paths that were not candidates this time; a secret-looking path is written only if the user ticked it by hand on that create (never seeded from a repo file or `.worktreeinclude`); an empty result: if the user saw the Review list (open at Create) or edited the ticks, a record with `paths: []` and a timestamp is stored (amended 2026-10-18: "record exists" means the user decided once, so the list does not reopen forever in repos that need nothing; no content, so nothing sensitive), otherwise nothing changes (a plain Create that never showed the list writes nothing); an existing empty record is left alone; an unchanged selection writes nothing (a `.worktreeinclude` seed stays live only while no record exists, until the user changes something); Cancel or a failed add saves nothing; a copy failure after a successful add still saves. **This time only:** when anything is ticked the line is a checkbox; unchecking skips copying and saves nothing. Paths are validated on read with the FR-630 hygiene; corrupt, wrong-shape or over-cap records are dropped without throwing. A remembered record only pre-ticks; it never authorises a copy. Nothing is ever written into the repo or `.git`, and GitHydra never writes `.worktreeinclude` in v1. The renderer loads from `file://` (all `file:` pages share one localStorage partition), so no remote or untrusted content may ever be loaded in a `file:`-origin window of the session.
- **FR-630 Copy engine (security-critical).** Copy file by file from the fresh git-enumerated set; a directory row expands to its enumerated files and is never copied wholesale (VS Code issue #329147: a broad pattern copied a whole directory over tracked files). Do not use `fs.copyFile` or `cp`. Source: open with no-follow (and `O_NONBLOCK`), `fstat` the handle (regular files only), compare its identity with the earlier `lstat` (the `sameIdentity` pattern of `editFile.ts`); where no-follow is a no-op (Windows) re-check `realpath(parent)` after the open; skip symlinks, junctions, FIFOs, sockets and devices without following or recreating them; check every parent component for a symlink or junction (`assertPathWithinWorkdir`, `resolveRealPathWithinWorkdir`, the `discardGuard.ts` parent check). Destination: apply the same parent checks inside the new worktree (a hostile repo's tracked symlink can redirect writes); create directories one level at a time with non-recursive `mkdir` and `lstat` each level; open the leaf with `wx` (exclusive create); stream handle to handle with the byte budget enforced while streaming; copy permission bits masked to `0o777` (never setuid/setgid; a 0600 `.env` stays 0600); never overwrite, never overwrite a tracked file; skip and report collisions, including case-insensitive and Unicode-normalisation collisions and the symlink-via-case case (tracked `Link` and ignored `link/x`). Path hygiene, applied to every candidate, memory and pattern: refuse (never sanitise) an empty path, NUL, control character, newline, bidi override, absolute or drive-relative path, `..` segment, `.git` segment, Windows reserved name (also with an extension, also `COM¹`/`LPT¹`), 8.3 short name, `\\?\` prefix, alternate stream (`:`), a trailing dot or space in any segment, or an over-length path (260 characters on Windows); the Windows rules apply on every platform. Copy limits: 5,000 files, 200 MB, 60 s, cancellable, progress after 2 s (git-core-engineer confirms the numbers). Names render as text nodes only. No scripts, no shell, no network, no secret contents in logs or messages.
- **FR-631 Reading `.worktreeinclude`.** Read-only. The file is opened once with no-follow and a regular-file `fstat` (a symlink is refused), at most 64 KB and 1,000 lines enforced while reading; the validated content is written to a private `0600` temp file and passed to git by that path, never the in-repo path (closes a swap-to-symlink race), and never executed. Matching is done by git, never hand-rolled: run the candidate listing of FR-626 (`--exclude-standard` only), run a second `git ls-files -o -i -X <temp file> -z` with NEITHER `--exclude-standard` nor `--directory` (and run the first listing also without `--directory` for the intersection; directory rows are built only for display), and take the INTERSECTION, so the include file can only narrow the set. Both flags matter: passing `-X` together with `--exclude-standard` would union the two rule sets and list non-ignored untracked files that merely match, and omitting `-i` would select the INVERSE set (the untracked files the include file does NOT name). `GIT_LITERAL_PATHSPECS=1` stays on; the file is never used as a pathspec. Reject patterns containing a `..` segment or a Windows-absolute path (`C:\`, `\\server`) as hygiene (listed under "Skipped: these patterns point outside the repository"); a single leading `/` is gitignore root-anchoring and is allowed (`/.env`). Real containment comes from the intersection with git's own enumeration of repo files. A file from a freshly cloned untrusted repo can therefore only select among ignored files that already exist in the source worktree, and the user sees every one by name before pressing Create.
- **FR-643 Two-phase copy, enforced in the main process.** Listing produces a main-held manifest (files, sizes, mtimes, per-directory counts) bound to a token. Create sends the token plus the selected rows, never raw paths. Main copies only files that are in the manifest and unchanged since review; anything else is skipped and reported "changed since you reviewed" (this closes the gap where a directory row expands to files the user never saw, for example a planted `.vscode/tasks.json`). The destination folder is chosen in the create dialog and validated by `specs/worktrees.md` FR-639. The token is single-use, expires after 10 minutes or when the dialog closes, and is bound to (repo key, source worktree id, the validated destination realpath chosen at Create time, the selected row ids); any change to the selected set invalidates it. Main re-runs FR-639 on the destination at copy time, not only at dialog time, and re-checks each entry's identity (dev/ino or size+mtime) against the copy-time handle (the `editFile.ts` pattern).
- **Result notices.** In-flow banners, persistent whenever anything was copied or skipped, never mentioning remembering: `Created worktree "feature-x". Copied 3 files (4 KB) from acme.` / `Created worktree "feature-x". Copied 2 of 3 files. Not copied: config/local.json (already exists).` / `Created worktree "feature-x", but nothing was copied: <reason>.`

## Non-goals (v1; `ROADMAP.md`)
Writing `.worktreeinclude` (a zero-write "Copy as .worktreeinclude" clipboard button first, later an explicit write command that says other tools read the file too); a manager or Settings section listing remembered files with Remove; pins, a per-row "always copy" control; saving on tick; post-create scripts; symlink or reflink instead of copy for dependency folders; union semantics between memory and `.worktreeinclude`; categories ("Env files", "Editor settings"); a "Forget" button (Select none then Create clears the record).

## Acceptance criteria
GC = git-core vitest with fixtures; JS = renderer vitest; PW = real Electron on the built app.
1. (GC) With a snapshot helper `snapshotTree(dir)` (sorted relpath -> {type, sha256, mode}), the source working tree and `.git` before and after a create differ only by `.git/worktrees/<name>/**` and, when a branch is created, the new ref, reflog and `packed-refs`; no GitHydra-written file; `.worktreeinclude` byte-identical; the new worktree contains only tracked files plus the copied set.
2. (JS pure) `decide(initialTicks, finalTicks, checkboxOn, candidates, record)` returns `none|write|delete` per FR-629: unchanged writes nothing (a fake `Storage` with `vi.fn()`; `setItem` and `removeItem` not called); an empty final set with the Review list seen or the ticks edited writes `paths: []` once (a repeat leaves it alone), otherwise nothing; record {a,b} with candidates {a}, unticking a and creating leaves {b}; a failed add or Cancel writes nothing; a copy failure after a successful add still writes; checkbox off writes nothing; a secret-looking path is in the written record only when it was ticked by hand on that create (never when it was only seeded from `.worktreeinclude`).

(JS pure) Storage failures (a `Storage` whose methods throw `SecurityError`), corrupt or wrong-shape records, paths with `..`/absolute/NUL/control/`.git`, over-cap records: dropped without throwing and without an error banner; the 201st path is dropped and the 201st record evicts the oldest (monotonic tie-break). ## Security review checklist (security-reviewer, before merge)
1. Renderer, memory and `.worktreeinclude` are hints only; the manifest in main (FR-643) is the authority; git-core re-enumerates.
2. FR-630 primitives in full (no `fs.copyFile`/`cp`, no-follow open + `fstat` + identity, one-level `mkdir` + `lstat`, `wx`, streamed budget, permission masking, hygiene on every platform, collision handling).
3. FR-631: private temp copy passed to `-X`, intersection of `ls-files -o -i --exclude-standard` and `ls-files -o -i -X` (both `-i`, neither `--directory`), size/line caps while reading, `..`/absolute rejection is hygiene only.
4. Memory: key via IPC (sha256), names only, validated on read, capped; secret paths written only when ticked by hand (owner decision; the reviewer must agree before merge); a repo cannot write it; renderer-supplied keys refused.
5. Run-code names never pre-ticked from a repo file; secret list is a table test; output hygiene (text nodes, bidi visible, no secret content in logs).
6. Token properties (single-use, expiry, destination binding, re-validation at copy time), listing DoS limits (kill on timeout, stdout and row caps), the key IPC with no argument.
7. No scripts, no shell, no network, no telemetry.
