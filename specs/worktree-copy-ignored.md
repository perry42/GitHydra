# Copy ignored files into a new worktree, with a per-repo memory, and into an existing worktree

Status: BUILT, not merged (branch feat/copy-ignored; security-reviewed with its changes applied, the reviewer agreed with remembering a hand-ticked secret on the condition that directory rows are classified by their contents, which is done; POSIX-only checks (O_NOFOLLOW, 0600, case-insensitive collisions) are not exercised on the Windows dev machine and should run on CI; see Review log; the owner can overrule). Split out of the worktrees spec on review (2026-10-13). Reviewed by security-reviewer, product-manager and test-agent; second security pass on the revised text pending (see "Review log"). Owner: product-manager. Needs a security review before build (copies files between folders). Companion of `specs/worktrees.md` (the create dialog's Advanced section). Owns FR-626..631, FR-643 and FR-649..657 (section G, copy into an EXISTING worktree, added 2026-10-19 after the owner approved the mockup `docs/design/copy-into-worktree/mockup.html`). Visual truth: the approved clickable mockup after the Impeccable fixes and the replacement of the Remember block. This text wins over the mockup.

## Problem
A new git worktree contains only tracked files. Ignored local files (`.env`, `.vscode/`, local config) are missing, and carrying them over by hand is tedious. Doing it silently would be dangerous: a secret could be copied somewhere the user did not expect.

## Target user
A developer who creates worktrees several times a week (or per agent session) and whose repos need a few ignored local files in every worktree.

## Product rules this spec must not break
Nothing is copied that the user has not seen named. No script runs. Nothing is written into the user's repo or `.git` by GitHydra. A file in a repo (`.worktreeinclude`) is untrusted input. No network, no account, no telemetry.

Principle: **the list remembers; the checkbox is for this time.**

## F. Behavior
- **FR-626 Candidates.** git itself lists them in the SOURCE worktree (the one the user created from): `git ls-files -o -i --exclude-standard -z --directory`. Directories are rows; a directory row shows a file count and size (size computed asynchronously and capped, with a "size not computed" fallback) and expands to its enumerated files at copy time. A nested repo or submodule directory is shown disabled ("separate repository, not copied"). Bare repo or zero candidates: render nothing. The git child process is killed on the 5 s timeout (the whole tree on Windows); stdout is capped at 4 MB and the manifest at 20,000 rows ("too many files to list" beyond that). git-core re-enumerates at Create time and refuses any requested path outside that fresh set; the renderer, the memory and `.worktreeinclude` are hints only.
- **FR-627 What is ticked on open.** In this order: (1) remembered paths that are still candidates (including secret-looking ones the user ticked by hand on an earlier create, see below); (2) otherwise `.worktreeinclude` matches that are not secret-looking, not on the run-code list below, and fit the budget (at most 20 rows, 20 MB in total, nothing flagged large); (3) otherwise nothing. Once a repo has a record, **including an empty one (`paths: []`, the user chose to copy nothing)**, the user's memory wins over the file: step (2) applies only when no record exists, so a `.worktreeinclude` that appears or changes later never re-seeds ticks or reopens Review for that repo. **Secret-looking rows are never pre-ticked from a repo file or from `.worktreeinclude`; they may be pre-ticked only from the user's OWN memory** (owner decision 2026-10-13, reversing the earlier "never remember"): a remembered secret such as `.env` is ticked on the next create, always shown with its secret warning on the collapsed line (FR-628), tagged "remembered" and "secret", and can be unticked in one click; a secret-looking path enters the record only if the user ticked it by hand on that create (FR-629). Security-reviewer agreement on this point is required before merge (it was the reviewer's recommendation to keep "never"; the owner chose convenience with these mitigations). Secret-looking = `.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `id_*`, `credentials*`, `.npmrc`, `.netrc`, `.pypirc`, `*secret*`, `*token*`, `*password*` (name-pattern based, so a false positive costs a warning and a false negative such as `config/local.json` is not caught; the list is a table test, implemented as simple prefix/suffix/substring checks, never backtracking regexes). **Run-code names** (`.envrc`, `.vscode/tasks.json`, `.vscode/launch.json`, `.vscode/settings.json`, `.idea/`, `.husky/`, `.githooks/`, `.devcontainer/`, `.claude/`, `.cursor/`, `.zed/`, `.cargo/config.toml`, `.yarnrc.yml`, `.yarn/`, `.mise*`, `.direnv`, `.mvn/`, `.bundle/`, `.pre-commit*`, `.lefthook*`, and, amended 2026-10-19 after the security review of section G (L3), the files that change how git or a tool behaves: `.gitattributes`, `.gitignore`, `.gitmodules`, `.lfsconfig` (can redirect the LFS endpoint), `.yarnrc` (`yarn-path`), `.pnpmfile.cjs`, `.npmrc` (`script-shell`, registry; also secret-looking), `.rvmrc`; a copied `.gitignore` or `.gitattributes` is additionally tagged "changes how git behaves in <B>" in section G; these are build-time table entries, extended as editors and tools add run-on-open config) run code when the new worktree is opened in an editor or shell: they are tagged "runs code when opened" and never pre-ticked from `.worktreeinclude`. **Large** = a directory named `node_modules`, `target`, `dist`, `build`, `.venv`, `venv`, `vendor`, `.gradle`, `Pods`, or any row of at least 50 MB or 5,000 files.
- **FR-628 The line and the Review list.** One line, always visible in the dialog body under "Open after create" (never inside Advanced, which holds only the detached-HEAD option; nothing is ever copied with the line hidden). With zero candidates it reads the muted line "No ignored files to copy in this repository."; in a bare repository, "This is a bare repository: there is nothing to copy." (amended 2026-10-18 after the owner never found the line inside Advanced). **Review default (amended 2026-10-18):** when this repo has NO record yet and at least one candidate, the Review list is open by default (`aria-expanded="true"`, focus stays in the Folder field) so the first create shows and teaches the ticks; when a record exists the one-line summary stays with Review closed (the user can open it). Zero-candidate, bare and failed states are unchanged. The list never scrolls on its own; the dialog body scrolls and the footer buttons stay visible. Warning marks are a triangle icon plus the word "secret", never colour alone. Exact strings (`·` is a middle dot, `...` is three dots, not an ellipsis character; sizes under 1 KB read `N B`, otherwise rounded to the nearest KB or MB with a minimum of `1 KB`; `1 file` vs `N files`; `1 secret file` vs `N secret files`):

  | State | Text |
  |---|---|
  | Checking | `Checking for ignored files...` (`aria-busy`) |
  | Candidates, nothing ticked | `No ignored files will be copied.` + `[Choose files]` |
  | Ticked from memory | checkbox (on) + `Copy 3 files · 4 KB` + muted `remembered for this repo`; second line `.env, .vscode/, config/local.json` (3 names, then `and N more`) |
  | Ticked from the file | checkbox (on) + `Copy 2 files · 3 KB from .worktreeinclude` |
  | A ticked row is secret | `[triangle] 1 secret file: .env` / `2 secret files: .env, .npmrc` |
  | File lists secrets, unticked | `[triangle] .env is listed in .worktreeinclude but looks like a secret, so it is not ticked.` (plural: `2 files listed in .worktreeinclude look like secrets, so they are not ticked: .env, .npmrc.`) |
  | Skipped this time | checkbox (off) + `Copy 3 files` + muted `skipped this time`, rows disabled but visible |
  | Listing failed or over 5 s | `[warning] Couldn't list ignored files. The worktree will be created without copying.` + `[Try again]` |

  After the user edits ticks, the "remembered for this repo" and "from .worktreeinclude" wording is dropped (it would no longer be true). Review expands: intro `A new worktree has only tracked files. Tick the ignored files you want copied.`; `[Select none]` only when something is ticked (no "Select all"); ONE list-level warning when a secret row exists (`Rows marked "secret" look like passwords, tokens or keys. Copy them only if the new worktree needs them.`); rows = checkbox + name + tags + size, ticked rows first, then rows listed in `.worktreeinclude`, then the rest; the list caps at 6 rows with "Show all N" (no nested scroller); tags: `secret`, `remembered`, `in .worktreeinclude`, `runs code when opened`, `large, consider reinstalling`; a symlink row is disabled (`symbolic link, not copied`); a name with control or bidi characters is shown with those characters visible and the row is disabled (`name not allowed`); `Skipped: these patterns point outside the repository` lists rejected `.worktreeinclude` patterns. Footer, the whole disclosure of remembering: `Changes you make here are remembered for this repository, on this computer.` A polite live region announces `3 files selected, 4 KB`. Keyboard order: Folder, Browse, copy checkbox, Review, rows, Select none, Cancel, Create.
- **FR-629 Memory.** One record per repository in the renderer's guarded `localStorage` (same pattern as `ignorePrefs.ts` and `useIdentityApplications.ts`; reads and writes never throw). The key is the sha256 `computeRepoKey` of the git common dir's realpath, **delivered over IPC by the main process** (`electron/recoveryDrafts.ts`; the renderer cannot compute a realpath; the key IPC takes NO argument and returns the key for the active repo only, like `session.getOpenRepo()` for recovery drafts, because a "key for path X" call would be a realpath-existence oracle; the key is not a security boundary, the record is only a hint), so the main checkout and every linked worktree share one record and two clones do not; the raw path is never stored. Value `{v:1, paths:[...], at}`; paths exactly as git reports them (directories end in `/`); no contents, sizes or hashes. Caps: 200 paths per record (the 201st is dropped), 200 records (oldest `at` evicted; ties broken by a monotonic counter). **Save rule:** on a successful `git worktree add`, with the checkbox on and the final ticked set different from the initial one (set equality over path strings; "visible" means candidate rows regardless of the 6-row cap), write the final ticked paths plus remembered paths that were not candidates this time; a secret-looking path is written only if the user ticked it by hand on that create (never seeded from a repo file or `.worktreeinclude`); an empty result: if the user saw the Review list (open at Create) or edited the ticks, a record with `paths: []` and a timestamp is stored (amended 2026-10-18: "record exists" means the user decided once, so the list does not reopen forever in repos that need nothing; no content, so nothing sensitive), otherwise nothing changes (a plain Create that never showed the list writes nothing); an existing empty record is left alone; an unchanged selection writes nothing (a `.worktreeinclude` seed stays live only while no record exists, until the user changes something); Cancel or a failed add saves nothing; a copy failure after a successful add still saves. **This time only:** when anything is ticked the line is a checkbox; unchecking skips copying and saves nothing. Paths are validated on read with the FR-630 hygiene; corrupt, wrong-shape or over-cap records are dropped without throwing. A remembered record only pre-ticks; it never authorises a copy. Nothing is ever written into the repo or `.git`, and GitHydra never writes `.worktreeinclude` in v1. The renderer loads from `file://` (all `file:` pages share one localStorage partition), so no remote or untrusted content may ever be loaded in a `file:`-origin window of the session.
- **FR-630 Copy engine (security-critical).** Copy file by file from the fresh git-enumerated set; a directory row expands to its enumerated files and is never copied wholesale (VS Code issue #329147: a broad pattern copied a whole directory over tracked files). Do not use `fs.copyFile` or `cp`. Source: open with no-follow (and `O_NONBLOCK`), `fstat` the handle (regular files only), compare its identity with the earlier `lstat` (the `sameIdentity` pattern of `editFile.ts`); where no-follow is a no-op (Windows) re-check `realpath(parent)` after the open; skip symlinks, junctions, FIFOs, sockets and devices without following or recreating them; check every parent component for a symlink or junction (`assertPathWithinWorkdir`, `resolveRealPathWithinWorkdir`, the `discardGuard.ts` parent check). Destination: apply the same parent checks inside the new worktree (a hostile repo's tracked symlink can redirect writes); create directories one level at a time with non-recursive `mkdir` and `lstat` each level; open the leaf with `wx` (exclusive create); stream handle to handle with the byte budget enforced while streaming; copy permission bits masked to `0o777` (never setuid/setgid; a 0600 `.env` stays 0600); never overwrite, never overwrite a tracked file; skip and report collisions, including case-insensitive and Unicode-normalisation collisions and the symlink-via-case case (tracked `Link` and ignored `link/x`). Path hygiene, applied to every candidate, memory and pattern: refuse (never sanitise) an empty path, NUL, control character, newline, bidi override, absolute or drive-relative path, `..` segment, `.git` segment, Windows reserved name (also with an extension, also `COM¹`/`LPT¹`), 8.3 short name, `\\?\` prefix, alternate stream (`:`), a trailing dot or space in any segment, or an over-length path (260 characters on Windows), or any code point in Unicode category Cf or with the Default_Ignorable_Code_Point property (zero-width, soft hyphen, BOM; amended 2026-10-19, L2: a `.g\u200Cit` look-alike is refused); the Windows rules apply on every platform. **Normative fold (amended 2026-10-19, L2):** collisions are compared on `NFD(toLowerCase(toUpperCase(NFC(x))))` of every path segment, on every OS (so `\u017F`/`S`, the Kelvin sign/`k` and `\u00DF` collide as the stricter filesystems do). **Windows links (amended 2026-10-19, M5):** `lstat().isSymbolicLink()` does not see cloud placeholders, WSL, dedup or mount-point reparse points, so on Windows a path component counts as a link when `lstat` says so OR when `realpath(component)` differs from the expected lexical path (compared case-folded after stripping any `\\?\` prefix); the second check is mandatory for every existing parent component, source and destination, not only the final `copyOne` check. **Residual risk, accepted (amended 2026-10-19, L5):** Node has no `openat`, so an attacker with write access to the destination can swap a parent for a symlink between the post-`realpath` check and the leaf `open` and cause an EMPTY file to be created and removed outside the destination (the engine detects it by identity and unlinks only its own inode); no content is ever written there. Each created directory is `lstat`-ed again before the final `rmdir` of a cancel/cleanup. Copy limits: 5,000 files, 200 MB, 60 s, cancellable, progress after 2 s (git-core-engineer confirms the numbers). Names render as text nodes only. No scripts, no shell, no network, no secret contents in logs or messages.
- **FR-631 Reading `.worktreeinclude`.** Read-only. The file is opened once with no-follow and a regular-file `fstat` (a symlink is refused), at most 64 KB and 1,000 lines enforced while reading; the validated content is written to a private `0600` temp file and passed to git by that path, never the in-repo path (closes a swap-to-symlink race), and never executed. Matching is done by git, never hand-rolled: run the candidate listing of FR-626 (`--exclude-standard` only), run a second `git ls-files -o -i -X <temp file> -z` with NEITHER `--exclude-standard` nor `--directory` (and run the first listing also without `--directory` for the intersection; directory rows are built only for display), and take the INTERSECTION, so the include file can only narrow the set. Both flags matter: passing `-X` together with `--exclude-standard` would union the two rule sets and list non-ignored untracked files that merely match, and omitting `-i` would select the INVERSE set (the untracked files the include file does NOT name). `GIT_LITERAL_PATHSPECS=1` stays on; the file is never used as a pathspec. Reject patterns containing a `..` segment or a Windows-absolute path (`C:\`, `\\server`) as hygiene (listed under "Skipped: these patterns point outside the repository"); a single leading `/` is gitignore root-anchoring and is allowed (`/.env`). Real containment comes from the intersection with git's own enumeration of repo files. A file from a freshly cloned untrusted repo can therefore only select among ignored files that already exist in the source worktree, and the user sees every one by name before pressing Create.
- **FR-643 Two-phase copy, enforced in the main process.** Listing produces a main-held manifest (files, sizes, mtimes, per-directory counts) bound to a token. Create sends the token plus the selected rows, never raw paths. Main copies only files that are in the manifest and unchanged since review; anything else is skipped and reported "changed since you reviewed" (this closes the gap where a directory row expands to files the user never saw, for example a planted `.vscode/tasks.json`). The destination folder is chosen in the create dialog and validated by `specs/worktrees.md` FR-639. The token is single-use, expires after 10 minutes or when the dialog closes, and is bound to (repo key, source worktree id, the validated destination realpath chosen at Create time, the selected row ids); any change to the selected set invalidates it. Main re-runs FR-639 on the destination at copy time, not only at dialog time, and re-checks each entry's identity against the copy-time handle (the `editFile.ts` pattern): when the platform reports a non-zero inode the dev/ino pair AND the size AND the mtime in nanoseconds must all match; size+mtime alone is allowed only when the inode is reported as 0 (amended 2026-10-19, L4).
- **Result notices.** In-flow banners, persistent whenever anything was copied or skipped, never mentioning remembering: `Created worktree "feature-x". Copied 3 files (4 KB) from acme.` / `Created worktree "feature-x". Copied 2 of 3 files. Not copied: config/local.json (already exists).` / `Created worktree "feature-x", but nothing was copied: <reason>.`

## G. Copy into an existing worktree
Problem: a worktree made earlier (or by a terminal or an agent) is missing the ignored local files a newer one got (`.env`, `.vscode/`, local config). Copying by hand is the same chore F removes, and the same secret risk applies. Target user: the same developer, with several long-lived worktrees. Default stance: GitKraken has no equivalent; this is an Improvement. All rules of F (FR-626..631, 643) apply unless overridden here. Visual truth: the approved mockup `docs/design/copy-into-worktree/mockup.html` is a picture only, never a source of markup or behavior; the owner decisions below and this text win over it. Built from the app's own components (CopyIgnoredSection / Review list, WorktreePicker), not from the mockup's markup; DESIGN.md and this text win over the mockup.

- **FR-649 Entry points.** The label is **Copy ignored files here...** on the two menus and **Copy ignored files into worktree...** in the palette (FR-656). It is an ADDITIVE item: it never replaces and never is replaced by the single Open/Create item of `specs/worktrees.md` FR-607. (1) Worktrees row menu (FR-613): order is Open worktree, Copy path, separator, **Copy ignored files here...**, separator, Remove..., so it never sits beside a destructive item. (2) The branch menu, only for a branch that has a worktree (the menu that shows Open worktree), directly after Open worktree; the destination is that branch's worktree. No item on a commit menu, on a branch without a worktree, or on the graph. Every item is a menu item with a leading worktree glyph; a disabled item uses `aria-disabled="true"`, stays focusable, and shows its reason as a second line wired by `aria-describedby` (never a native `disabled`, never hidden, never a toast).
- **FR-650 Source, destination, refusals.** Source = the worktree of the ACTIVE tab (the main checkout for the repo's own tab, the linked worktree for a worktree tab). Destination = a worktree id (admin-dir name, `null` for the main worktree) taken from main's own worktree list (`specs/worktrees.md` FR-601); it is never typed, browsed or sent as a path. The item is disabled up front, with these exact reasons, for: the source itself `This is the source worktree`; locked `Locked: unlock it first`; prunable or missing `The folder is missing`; a `supported: false` entry or an `untrusted` list `This worktree list could not be read safely`; a bare repository (item disabled on every row) `This is a bare repository: there is nothing to copy.` A destination in a network-path record is `supported: false` and is refused the same way. The item is NOT disabled for "no ignored files": that is known only after the asynchronous listing, so the item stays enabled and the dialog says it (FR-651). When the dialog opens, main re-runs FR-640 steps 1 to 4 on the destination (the main worktree is checked by realpath equality with the main workdir instead of the back-link) and compares the realpath with the list; a failure shows the in-dialog error `Not a worktree of this repository.` and nothing is listed or written. Source and destination must be different realpaths, and (amended 2026-10-19, M4) must not be ancestor and descendant of each other unless the inner one is excluded: a candidate path whose realpath is the destination, or that contains it, is a disabled row tagged `contains <B>` (layouts `A/.worktrees/B` and A inside B), and the expansion of a directory row never descends into a directory that has its own `.git` file or directory. **Main worktree (L6):** its workdir is the first entry of `worktree list -z`, verified with `git rev-parse --git-common-dir` in it equal to the bound common dir; never `commondir/..` (wrong for `--separate-git-dir` and `core.worktree`). Open as a tab is NOT required or checked; a dirty destination is allowed (files copied are untracked/ignored, nothing tracked is touched).
- **FR-651 Dialog.** Standard shell, 540 px (the mockup width), title `Copy ignored files`, Esc cancels, sticky footer, only the body scrolls, fits an 800 px high window. Owner decisions 2026-10-19: (1) layout is ONE sentence `From <A> into <B>.` (A and B in bold = the worktree FOLDER names; if both folder names are equal, the full paths are used) with the destination's absolute path under it as muted selectable text (`overflow-wrap:anywhere`); no two-row variant. (2) With zero candidates the body is the muted line `No ignored files to copy in this repository.` and the footer has a single **Close** button (primary, initial focus). (3) Focus starts on the first ENABLED row's checkbox (not on Copy); Enter anywhere in the dialog presses Copy when something is ticked, with these guards (amended 2026-10-19, M1): Enter presses Copy only for a non-repeat keydown that follows a keyup observed inside the dialog; the dialog ignores every key event for its first 400 ms; Enter never presses Copy while any ticked row is tagged secret, `runs code when opened` or `not ignored in <B>` unless the focus is on the Copy button itself; Space ticks; if no row is enabled focus starts on Cancel/Close. (4) Skipped files are reported in the banner (FR-655). Body: intro `Tick the ignored files you want copied. Files that already exist in <B> are never overwritten.`; `[Select none]` only when something is ticked (no Select all); the single list-level secret warning and all row tags/size/sort/6-row cap/`Show all N`/live region of FR-628, using the same strings; one footer sentence `Changes you make here are remembered for this repository, on this computer.` (true, FR-654). Listing states: `Checking for ignored files...` (`aria-busy`, Copy aria-disabled); on failure or over 5 s `Couldn't list ignored files.` + `[Try again]` (new listing, new token). Footer readout (polite live region): `N files selected, X KB` / `No ignored files will be copied.` (muted) / `Over the limit of 5,000 files or 200 MB. Untick something.` (critical ink, Copy aria-disabled). Footer buttons: `Cancel` and primary `Copy` (aria-disabled when nothing ticked or over the limit; Enter then does nothing). Keyboard order: first row..last row, Select none, Show all, Cancel, Copy. Focus returns to the invoking menu button/row (palette: to the previously focused control) on close. Everything in the dialog is text nodes; names with control or bidi characters are shown with them visible and the row is disabled `name not allowed`. **Names come from main (amended 2026-10-19, L1):** the folder names A and B, the destination path and the destination id shown in the dialog and the banner come from main's listing and copy responses, never from the renderer's own worktree list. Control, bidi and format (Cf) characters in A, B, the path and every skipped name are shown escaped as visible `U+XXXX`, and any single name is truncated to 120 characters in the middle. **Counts and order (settled 2026-10-19):** the directory row line is `1 of 3 already exist` / `N of M already exist` (the verb is `exist` for every N); the over-limit check counts only ENABLED TICKED files, never skipped ones; the strongest tag of a row is chosen in the order `inside another repository` > `destination folder is a link` > `tracked in <B>` > `already exists`.
- **FR-652 Listing and existing-destination rules.** Main lists in the SOURCE exactly as FR-626 (same caps, timeout, nested repo/submodule rows disabled, `.worktreeinclude` per FR-631, tags per FR-627/628) and then classifies every enumerated file against the DESTINATION, without following anything: (a) the leaf exists in any form (file, directory, symlink, junction, FIFO, socket, device) or collides case-insensitively or by Unicode normalisation with an existing sibling: `already exists`; (b) any parent component inside the destination is a symlink, junction or reparse point, or resolves outside the destination realpath (checked per component with `lstat` plus, on Windows, the mandatory `realpath` comparison of FR-630, M5), or is a regular file: `destination folder is a link` (or `already exists` for the regular file); never followed, nothing created below it; (c) the path is TRACKED in the destination (asked of git through the git-core worktree seam `wtRun`/`wtSpawn`, which prepends `-c core.fsmonitor=false -c core.hooksPath=<private empty dir>`, argv array only, `GIT_LITERAL_PATHSPECS=1`, after the FR-640 checks passed, compared with the FR-630 fold). **Hardening (amended 2026-10-19, M6):** EVERY read-only git call of this flow goes through that seam, which removes `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`, `GIT_NAMESPACE` and `GIT_CEILING_DIRECTORIES` from the environment; before the tracked check, `git rev-parse --show-toplevel` and `--git-dir` run in the destination must equal the realpath bound by FR-653 and the destination's admin dir, else the listing fails closed; a `dubious ownership` refusal fails the listing closed with the same message as any other tracked-check failure and `safe.directory` is NEVER overridden (no `-c safe.directory=*`). **Asking (M7):** per batch of at most 2,000 candidate paths with `git ls-files -z --cached --stage --` (the index including unmerged and intent-to-add entries; HEAD is not consulted), each batch with the 5 s timeout, 4 MB stdout cap and kill-tree of FR-626; ANY timeout, cap hit, non-zero exit or unparsable output fails the listing and the copy closed. A tracked directory or gitlink entry that is a prefix of the candidate path also means `tracked in <B>`. Classification of all rows against the destination shares ONE overall deadline of 15 s; rows not classified in time are disabled (`could not be checked`), never enabled. **Nested repositories (M3):** a destination directory that contains a `.git` entry (file or directory) at any level of the path below the destination root is `inside another repository`: the row is disabled and nothing is created below it, checked with `lstat` of `<dir>/.git` at each existing level) or lies inside a destination submodule or inside `.git`: `tracked in <B>` (a submodule or nested clone is `inside another repository`) (a tracked file is NEVER overwritten, on every OS, must-pass); if git cannot answer, the whole listing fails closed with `Couldn't check which files <B> tracks.`; (d) source symlinks, hygiene failures (FR-630), directory rows that are separate repositories: disabled as in F. A FILE row failing (a)-(c) is disabled, never ticked, with its tag (`already exists`, `destination folder is a link`, `tracked in <B>`). A DIRECTORY row is enabled while at least one of its enumerated files can be copied; if some already exist it shows `N of M already exist` and only the rest is copied; if none can be copied it is disabled with the strongest tag. Informational tag `not ignored in <B>` (muted; with a warning triangle when the row is also secret) on a row whose files git would NOT ignore in the destination (`git check-ignore --no-index`-equivalent, asked of git in the destination under the same safe flags; if that check fails the tag is simply absent, nothing else changes); it never blocks. Directories are created one level at a time (non-recursive `mkdir`, `lstat` each level, never inside `.git`), files are opened `wx`, streamed and permission-masked exactly per FR-630; a `wx` failure because another process created the same leaf mid-copy is reported `already exists`, not an error; there is no replace/overwrite control in v1. Every state is re-checked at copy time (FR-653), so a listing-time classification is advice only.
- **FR-653 Manifest, token and authority (security-critical).** Same two-phase design as FR-643, as a distinct token PURPOSE `copy-into-existing` (a token minted for Create can never be redeemed here, and the reverse).
