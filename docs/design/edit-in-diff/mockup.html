Why this is better than GitKraken

  • Editing is labelled, not just tinted. An "Editing" tag with a pencil, a raised editor frame and a status footer. GitKraken's cue is an "editable" tag plus a blue dot.
  • Unsaved is shape plus a word where it matters, and quiet where it does not. Header: dot + "Unsaved". File list: only an 8px dot (hidden text "Unsaved changes", tooltip). GitKraken's documented cue is a colour-only blue dot.
  • As much room as GitKraken, your choice of how. B (default) widens the drawer to 80% and folds the file list into a hover/focus rail; C takes the whole window like GitKraken (graph hidden, Esc or the same button restores); A keeps today's drawer. The editor line count is shown under each window.
  • You keep your review context without spending width. Gutter markers (added / modified / removed vs HEAD) stay in the editor and clicking a removed marker peeks the deleted lines in place. GitKraken drops all HEAD context once you edit.
  • Two header buttons, no chips. Header is two rows at most, the action row never wraps. Save and stage is secondary, Save is the one filled button; shortcuts live in tooltips and a keys strip. "Stage saved changes only" is gone (hunk/line staging covers it).
  • A real code-editor Tab. Tab indents every selected line, Shift+Tab outdents, indent unit follows the file, and Ctrl+M is the documented way out to the toolbar. Esc is ignored mid-IME composition; shortcuts also work on non-Latin layouts (Hebrew) via the physical key.
  • Leaving or overwriting can't lose work by accident. Leave, Reload and Overwrite open a window-anchored dialog in ConfirmDialog's shell with the safe button focused. On-disk changes show as ONE banner line pinned inside the editor, never pushing your text (FR-473/474).
  • Edit is never silently missing, and easy to find. Double-click, Edit button, E, right-click "Edit file", Command Palette. Ineligible files show the reason beside the button; double-clicking one flashes it.

GitKraken behaviours the docs do not specify (exit wording, ineligible files, leave trigger) are marked "assumed" in the GitKraken captions.

Open decisions

Already decided by you

  • Double-click enters edit mode (kept, with the visible Edit button and the E key). The mock ignores the checkbox column, hunk header and Discard, and keeps the clicked line at the same screen row with the caret at the clicked column.
  • Autosave: dismissed (stays a non-goal).
  • Right-click "Edit file" on file rows, and Command Palette entries (Edit file, Save, Save and stage): in.
  • Encoding dropdown: shown as an option here (toggle in the top bar). Saving never changes encoding.
  • Layout: B as default, C available (decided direction; confirm after trying the Layout control).

Still open

  1. Does v1 support non-UTF-8 files? FR-469 only promises BOM, line-ending and final-newline round-trip. Recommend v1 = UTF-8 (+BOM) only: other encodings get Edit disabled with "Not UTF-8", and the footer shows the encoding as plain text. The dropdown (reopen as another encoding, saved back in that same encoding) then ships later with a decoding library (iconv-lite is MIT; needs the licensing check). Say which and I will drop or keep the dropdown.
  2. Expand shortcut. I used Ctrl/Cmd+Shift+Enter: F11 is Electron's native fullscreen, so it would toggle the OS window instead. Esc restores first, a second Esc leaves the editor.
  3. Banner overlays the first visible line (it must not push text). If the caret sits under it the editor scrolls one line. Alternative: a thin 3px marker only, details in the header. Recommend overlay.
  4. Save and stage: leave the editor or stay? Recommend leave: the file moves to Staged, which is read-only (FR-468), with a "Saved and staged" note.
  5. Primary button: Save (recommended) or Save and stage?
  6. Leave prompt focus: Save (recommended); Discard is never focused. Reload and Overwrite focus Cancel.
  7. Peek keyboard path. Mouse: click the red marker. Keyboard: Alt+Shift+D at the caret. OK, or drop peek from v1?
  8. Scope flag for product-manager: FR-467 says the file list "stays visible"; layout B collapses it to a rail while editing. Not in the spec at all: right-click entry, Command Palette entries, Expand, gutter markers and peek, encoding dropdown, Tab/Ctrl+M behaviour. Each needs an FR or an explicit cut.
